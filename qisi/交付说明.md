# qisi API 本地版本

基于 New API（QuantumNous，AGPL-3.0）制作，源项目署名与许可证保留。代码独立于 qisiTV；没有改动 cheeser.link 线上站点。

## 使用

本地地址：http://127.0.0.1:4319/api-service/

管理员用户名和随机密码在 `.local-tests/admin.json`，文件仅当前系统用户可读。登录后可更改密码。不要上传此文件、数据库、运行日志或上游 Key。

重启：可双击 `qisi/启动本地.command`，或在项目目录执行 `python3 qisi/start-local.py`。前端或 Go 代码改变后需重新构建；运行中程序不会热更新嵌入的网页。

构建：

```sh
cd web
bun install --frozen-lockfile
QISI_BASE_PATH=/api-service bun run build
cd ..
go build -ldflags '-X github.com/QuantumNous/new-api/common.Version=v0.1.0-qisi-preview' -o .local-tests/qisi-api .
python3 qisi/start-local.py
```

首次初始化脚本 `python3 qisi/bootstrap-local.py` 只操作本机 4319 端口，会建立管理员、设置品牌、安装 LikeAI 插件、关闭注册并把初始余额设为零。已有初始化实例不会被脚本覆盖。

## 手动充值 / 调整额度

后台「用户管理」→ 用户的「编辑」→「手动充值 / 调整额度」。

- 增加余额：用于线下已收款或赠送额度。
- 扣减余额：用于纠错。
- 设置余额：直接设置目标余额，需仔细核对。
- 提交前显示调整后的余额；前端阻止同一次请求处理中重复提交。
- 管理员权限、金额上限、余额事务与操作日志沿用 New API 原有机制。
- 操作日志保留操作人、时间、对象、调整前后余额；用户日志有充值类型记录。
- 手动调整不创建虚构的在线支付收据，也不等于实际收款。
- 余额展示为人民币，内部额度与美元的转换沿用系统配置；当前 7.3 仅为底座默认转换配置，**不是实时汇率或已确定的销售价格**。开售前统一核对展示汇率、售价、充值换算。

## LikeAI 与付费开关

`qisi/likeai.plugin.js` 是首版任务适配器，后台「任务插件」可管理。仅适配 Seedream 4.5、Seedance 2.5 的文档参数，开放自有 Key 鉴权的 `/likeai/task/create_task` 与 `/likeai/task/query_task/:task_id`。不宣称 OpenAI 接口兼容。

未录入上游 Key、未建立付费渠道、未配置零价模型；本次没有提交任何付费生成。管理员完成成本/转售条款和售价核对后，创建类型 61 的任务插件渠道，绑定 `qisi-likeai`，上游地址仅为 `https://task.likeai.pro/task-api`。密钥仅服务端保存。图像按张、视频按指定秒数配置动态计费及分辨率价格；不要把按次价格误当按秒价格。

重试次数设为 0。LikeAI 未提供已核实的幂等创建协议，提交超时可能已被上游接受；商业启用前需补充对账流程及一次明确预算授权的端到端生成测试，不能把超时当作可免费重试。当前插件验证属于模拟响应合同测试，不能代替真实计费验收。

## 在线支付

钱包及支付配置沿用底座的真实支付流程，未开通商户时显示不可用，不使用模拟付款结果。当前没有商户，不能收款。

已有适配包括 Stripe、Creem、Epay 等。支付宝/微信官方直连不应被误称为已完成，需根据用户的企业/个体户或海外主体资格选择渠道；未知代收站不作为默认方案。确认渠道并取得商户配置后，必须验证签名、重复回调、金额与订单对应、退款/对账，再开放充值。

## 部署到 cheeser.link 栏目

持久化后台部署使用 `qisi/compose.yml`。先复制 `.env.example` 为同目录 `.env` 并替换随机 SESSION_SECRET。Docker 当前机器未安装，因此 Compose 未实跑；本地已实际验证的是 Go 二进制运行。

1. 确认后台服务器及 HTTPS 源站地址。云端保留数据库卷，做定期备份和恢复验证。
2. 初次配置通过 SSH 隧道完成，不能向公网暴露未初始化后台。生产账户在生产实例单独设置，不复制本机测试密码。
3. 后台系统地址设置为 `https://cheeser.link/api-service`；生产必须保留 Secure Cookie 与可信来源 `https://cheeser.link`。
4. 将 `vercel-rewrites.example.json` 的规则合并到现有网站配置，替换真实后台地址；不要覆盖现有 qisiTV 的规则。
5. 服务器/代理保留 `/api-service` 前缀，后端自行剥离。核查代理响应的 Cookie、缓存、上传体积与超时，禁止缓存登录/余额/Key 接口。
6. 发布修改版时提供对应源代码，并保留 New API / QuantumNous 的署名与 AGPL 许可证。

当前服务器位置尚未确定，未发布到 cheeser.link。数据库、支付渠道和售价不会由静态栏目部署自动获得。
